# Explicit process entropy reference profile

`ProcessEntropy::from_os(Abi::Horizon64EntropyReference)` reads exactly 32 host `getrandom` bytes once on Linux and retains four immutable u64 words for that configured process. Short reads and interruptions are handled; source errors refuse construction rather than supplying fallback zeros. No random read occurs inside a service callback and no values are logged. Cloned profiles/registry views retain the same source. `from_synthetic_words` explicitly supplies deterministic test fixtures.

The opt-in registry contains only GetInfo (SVC 0x29), and only its RandomEntropy information type 11 is supported. W1 supplies the information type, W2 the handle and X3 the full 64-bit subindex. Handle zero is required; indices 0..3 return W0 success and the selected complete u64 in X1. A bad handle reports reference InvalidHandle (0xe401); a bad subindex reports InvalidCombination (0xe801), with handle validation first. Failed replies retain unspecified X1, without claiming retail failure-output bits. Other GetInfo types refuse internally; no address, memory, clock, core or firmware answer is guessed.

This is configured host process state under an inspected reference convention. It does not authenticate process policy, verify retail Switch 2 behavior or authorize original functions. Default registries remain empty. Compose explicit registries with `Services::combined`, which rejects duplicate numbers and the existing 256-handler limit; then apply the final process allowlist with `restricted_to`. Combining profiles is not permission authentication.

The actual supplied SDK initialization path statically requests this information type with handle zero and subindices 2 and 3. This establishes a concrete dependency, not an execution trace. The requesting constructor itself still rejects under the unchanged strict CFG rules at its abort path; implementing entropy does not make it runnable. See [BOOTSTRAP_REUSE.md](BOOTSTRAP_REUSE.md).

Two unit tests cover complete/short/interrupted/failed sources, zero/oversized responses, immutable sharing and real OS construction without randomness statistics or value logging. One native integration test runs original synthetic SVC/RET and monitor fixtures at O0/O2 with fatal UBSan. It checks all four words, stable/cloned/distinct fixture sources, argument widths, error priority, unsupported/default registries, exact budgets, register preservation and handled versus unsupported monitor effects. Existing QEMU transport/monitor tests remain required; Linux QEMU is not a Horizon GetInfo oracle.
