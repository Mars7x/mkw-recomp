# Source-scoped normal-return evidence

`mkw_arm64::terminal::Image` owns an immutable, hashed AArch64 text image. `analyze(entry, bytes, facts)` walks every reachable conditional path and records all decode/missing-edge issues. Ordinary calls may return and retain their continuation. Only opaque evidence for an exact local entry can remove a call continuation or establish a terminal direct tail. RET/authenticated RET and unknown indirect/external tails remain possible normal returns. A conditional edge bypassing a terminal call stays blocked.

`Analysis::no_return_fact()` creates evidence only for an issue-free graph without a possible normal return. Unknown decodes continue diagnostically so later issues remain visible, but prevent certification. A previously established terminal call can make subsequent bytes unreachable; this does not change the existing decoder or lifting policy. The evidence derives from code and control, never a function name or caller-provided boolean.

Image clones share one immutable namespace. Facts from independently created images reject even if their bytes/hash match; duplicates and direct assumptions of the current entry also reject. Each fact retains its source and supporting derivation objects. Source/body hashes and a versioned derivation digest identify evidence; they do not authenticate loaded native code, a process or retail permissions. NoReturn objects cannot be constructed or deserialized from metadata. The analyzed body limit is 1 MiB, matching the existing survey bound.

This establishes only a normal-return property in the existing non-unwinding checked control model. It does not promise success, progress, termination, hardware behavior or absence of diagnostic faults. Guest exceptions, asynchronous signals and debugger resumption are not modeled. No import/GOT alias, cross-image fact or runtime target assumption is accepted by this initial API. In particular, an initially bound import must not be treated as immutable without later target/code guards.

Existing lifters, emitters, loaders and routers do not consume this evidence. Strict/default and all current conditional admission rules, truncated-CFG negatives, CPU/table layouts and original-execution gates remain unchanged. No terminal-call lowering, runtime guard, fake return or bootstrap replacement is installed.

## Evidence

Six new source-analysis tests cover closed loops, local dependency chains, returning branches, an escaping conditional bypass, complete decode issues, source ownership/namespaces, duplicate/recursive/foreign/wrong-target facts, authenticated returns, dynamic tails, unreachable bytes, source mutation and bounds/overflow. A seventh native test compiles an independently authored load/add/store/branch loop at O0/O2 with fatal UBSan. Across two initial counters, budgets 0..64 and both optimizations, 260 budget traces check exact PC/register/memory/wrap behavior; two invalid-pointer traces check fault exits. Finite native observations support the implementation tests; the graph analysis establishes the stated structural property. Existing QEMU instruction/monitor checks remain required, rather than claiming a finite QEMU run proves non-return.

`terminal-proof-check GAME_ROOT` first verifies exact supplied identities and segment hashes, then compares against unchanged default lifting. It certifies 21 already accepted, return/escape-free bodies: nine main, seven SDK and five subsdk0; none rtld. Detailed stamps/addresses remain private. This is an additive required source check, not 21 new accepted or runnable functions. No original function is generated or executed by the check.

Separate private analysis considers guarded terminal-call assumptions across all 9,335 rejected extents. Its 7,286 candidates remain counterfactual and unverified by this local-only API; they are not coverage gains. The next dependencies are checked import witnesses, conditional proof propagation, native code/target attestation and contradictory-return refusal, followed by independent tests before any lowering. Preserve all existing admission rules and explain any compiler/bootstrap architectural tradeoff before changing it.

The implementation is original Rust, using the project's existing decoder and already pinned RustCrypto SHA-256 dependency. No upstream kernel implementation or game-derived code is incorporated into distributable source.

## Exact import source witnesses

`Image::import_thunk(entry, max_veneers)` recognizes zero to eight exact direct `B` veneers followed by `ADRP x16; LDR x17,[x16,#offset]; ADD x16,x16,#offset; BR x17`. Both offsets must identify the same slot. Fixed opcode/register/width bits, signed page/branch displacement, text bounds and checked address arithmetic are enforced. Cycles, excessive chains, calls substituted for veneers, mismatched offsets, unsupported variants and wrapping addresses refuse. This intentionally covers one bounded form rather than guessing other stubs.

The opaque `ImportThunk` owns its immutable image and retains a source stamp for every veneer and the four-word body. It records the effective slot address: the final x16 value; x17 receives the loaded 64-bit target and x30 is preserved. The slot may lie outside text and is never read by source recognition. Namespace checks distinguish independently created images even when hashes match. A witness cannot mint `NoReturn`, provide a symbol/relocation binding or authenticate loaded native code. Existing terminal analysis still treats the indirect tail as possibly returning.

`import-witness-check GAME_ROOT` uses the existing checked diagnostic loader/relocator and correlates recognized source with exact zero-addend JUMP_SLOT records, symbol selection and slot readback. Across the supplied modules, 11,074 exact source forms yield 11,070 relocation correlations and 11,064 selected providers; six correlations have weak-null providers. Four forms lack the selected relocation and remain source observations. Source addresses, symbols and binding details stay private. Initial binding and diagnostic layout do not prove immutable targets or Switch 2 runtime compatibility.

Four source tests cover 3,584 signed-page/offset combinations, every fixed-bit mutation, all 4,096 load immediates, offset mismatches, namespaces, ownership, bounded forward/backward veneers, cycles, truncation and arithmetic refusal. One native/QEMU test uses independently authored fixtures with zero/one/eight veneers, three offsets including 4,088 and two real returning targets. Eighteen QEMU cases agree with generated native C at O0/O2 with fatal UBSan. Native runs check 648 exact budget/register/PC traces and 36 unregistered-target refusals; repeated writes to the same slot switch the actual target while the source witness stays unchanged. This is evidence that source recognition alone is insufficient for a terminal effect, not a runtime target guard.

The remaining dependency is a conditional import/normal-return proof with source-attested compiled targets and guards on the actual routed target chain, including contradictory normal-return refusal. An initial GOT check alone has a check/use mutation gap. Keep source, compiler/verifier identity, proof obligations and loaded libraries alive together before any effect is consumed. No compiler lowering, admission rule, ABI header or bootstrap sequence changes here; measured strict/conditional gain remains zero.
