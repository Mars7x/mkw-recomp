# Event reference handlers over owned object tables

`TableEventServices::new(Abi::Horizon64EventReference, table).registry()` explicitly binds SignalEvent (0x11), ClearEvent (0x12), ResetSignal (0x17), CloseHandle (0x16) and the zero-timeout event subset of WaitSynchronization (0x18). Real producers must supply owned endpoints through the host APIs in [KERNEL_HANDLES.md](KERNEL_HANDLES.md). No CreateEvent, IPC response, clock or implicit game registration is installed. The legacy event-only registry remains separate; duplicate SVC registrations reject when combining registries.

Signal/reset require a typed write/read endpoint respectively; clear accepts either. Close removes a real owned table entry and drops its reference after releasing the table lock. A transferred read endpoint observes the producer's persistent manual-reset state after source closure; closing one duplicate retains other references and the underlying object quota. Endpoint capability errors use the selected reference results in [EVENT_SERVICES.md](EVENT_SERVICES.md); unspecified error outputs remain unchanged, without asserting retail output bits.

For a zero-timeout poll, the complete checked little-endian u32 guest array is copied and every typed table entry is pinned under one table lock. The pinned read endpoints must share the same event backend; its lock then supplies one first-ready snapshot without consuming the signal. Cloned factories share that backend. Mixing independent backends refuses internally instead of approximating an atomic snapshot. Count zero returns the selected TimedOut result without reading the pointer; signed W2 counts outside 0..64 report OutOfRange. Nonzero/negative timeouts and process-pseudo reset refuse before effects. Checked guest read failures remain transport diagnostics, not invented kernel pointer results.

No pending cancellation/termination, thread/process wait objects, blocking or time model is supplied. This is a synthetic reference subset, not a verified Switch 2 kernel. Exact identity/configuration gates still precede original execution. Compose explicit profiles before applying the final process allowlist; `Services::combined` rejects conflicts and the existing quota, and never silently overrides an earlier handler.

Three O0/O2 fatal-UBSan native tests pass debug/release. They check real imported endpoint state/rights/lifetimes, all 64 slots/index 63, duplicates, complete validation despite an earlier ready handle, stale/foreign/wrong-type rejection, quota release, argument widths, invalid counts/pointers, exact budgets, unsupported mixed backends/timeouts/default registration and handled versus refused monitor effects. A composition test exercises entropy and event handlers together, a denied signal with unchanged state, explicit success through the unrestricted view, conflicting registrations and the 256-handler limit without invoking a handler during composition. Existing tests, native/QEMU checks, ABI definitions and compiler acceptance remain unchanged.

State comes from the existing attributed MIT event primitive. The Rust table adapter is original code and retains all existing notices/provenance. Reference facts/file identities remain those in event-services-reference.json. No original game/SDK code, IPC exchange or frame has executed.
