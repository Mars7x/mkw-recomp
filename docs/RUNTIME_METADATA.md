# Declared kernel capability facts

`mkw_formats::capabilities::KernelCapabilityFacts::inspect` extracts selected reference capability fields from already parsed NPDM words. It exposes declared numeric priority/core ranges, SVC mask bits, program type, intended kernel version, shared handle-table entries and debug flags. Missing records stay absent; no default target settings or permissions are invented. Duplicate singleton records or SVC groups, reserved bits, inverted ranges and unsupported descriptor kinds refuse the whole inspection. Padding is ignored.

`runtime-metadata-check GAME_ROOT` first verifies the exact supplied ExeFS identities, rechecks the parsed NPDM hash, checks the main thread against declared numeric ranges and page-aligned stack size, and records facts only under private/analysis. It activates no service and does not authorize original execution. This consistency probe is an additive required publication check.

`Services::restricted_to` returns a registry view containing only previously registered handlers whose numbers appear in an explicit allowlist. Filtering can remove handlers, never add them. Views retain the same underlying service state; the original registry is unchanged. This is a capability restriction helper, not signature authentication or a complete kernel SVC-access exception model. Denied calls retain the existing diagnostic unsupported status, with no fabricated guest result or service effect.

These are metadata facts, not authorization. Inspection neither verifies an ACID signature nor implements complete loader restrictions, physical mappings, actual core availability, retail firmware identity, PAC/TBI/virtual-address configuration, TLS templates or startup. A declared intended kernel version is not the running retail kernel version. Numeric core ranges do not establish host affinity or scheduling behavior.

An exported SDK SVC wrapper can exist even when its number is absent from the application's declared permissions. Selecting a synthetic service registry must not grant additional process permissions. Events obtained from another service also require real transferred-handle ownership; a locally created synthetic pair is not a substitute for an IPC-provided object. The shared handle-table entry limit counts endpoints and other object types, and must not be reused as a per-event object quota.

Three format tests exhaust every bit in all eight SVC groups, combined masks, missing/padding records, numeric and quota boundaries, duplicates, reserved fields and unsupported kinds. One additional O0/O2 fatal-UBSan native test checks empty/narrowed/unknown allowlists, denied CreateEvent register/budget preservation and quota nonconsumption, permitted execution and shared state. All four new tests pass debug/release. Existing QEMU transport/monitor comparisons remain required; no new guest ISA semantics are introduced. An independent private Rust/Python extraction also compares the supplied hash-verified metadata. This does not execute original code or change compiler acceptance. Existing native/QEMU correctness checks and identity/configuration gates remain required.
