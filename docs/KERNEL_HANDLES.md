# Owned object references and explicit handle transfer

`kernel_handles::Table` owns typed `Arc` object references behind explicit diagnostic handles. Each table receives an entry quota in 0..1023; zero permits no entries. Entry quotas count handles, separately from an event factory's object quota. Single and paired insertion validate capacity before publication; pair insertion publishes both entries together. Failed insertion retains normal object cleanup.

Tables and the existing event primitive share one monotonic, non-reusing identity allocator below 0x40000000. This avoids collisions between namespaces while keeping owner/waiter tag bits outside identities. It is a diagnostic identity policy, not verified retail handle index/generation encoding. Exhaustion refuses without wrap or partially consuming a pair.

`export` pins an actual object from a live source entry. `import` consumes an owned pin to create a new destination entry with a new handle. Closing the source after export does not destroy the pinned object; closing the imported entry does not destroy references held elsewhere. Foreign and stale raw handles refuse. Typed lookup rejects another Rust object type. Batch lookup snapshots and validates every entry under one table lock, then releases the lock before callers inspect objects. Duplicate input handles pin the same object without creating entries.

Export/import are explicit host capability operations. They do not implement a Horizon IPC packet, copy/move rights policy, descriptor validation, process authorization or move-handle semantics. No guest service can invoke them implicitly. Host callers must validate real transfer contracts before using these operations for a game.

`shutdown` permanently prevents insertion/import and drains the complete map before dropping any payload. Payload destructors run outside the table lock, including destructors that reenter the table. Exported and lookup pins remain owned references until released. Explicit host teardown must invoke shutdown to break payload-to-table `Arc` cycles. This is not a Horizon process/thread exit, cancellation or scheduling implementation. Arbitrary trusted host payload destructors can still panic; this API is not a sandbox or general cycle collector.

`owned_events::Factory` creates real paired endpoints using the existing attributed MIT event primitive. Typed read and write endpoint objects expose the corresponding state operations; their final references close the internal endpoints. A transferred read endpoint observes the actual producer's persistent signal, remains readable after the write endpoint closes and retains the object's quota until its own final reference drops. Failed table pair publication closes both newly created internal endpoints. No fake IPC response or event signal is supplied.

Six new tests pass focused debug/release checks: allocator exhaustion, four table/state/ownership tests and one generated-native fixture. Eight host clients perform 1,600 object cycles with 3,200 distinct table handles. Native fixtures run at O0/O2 with fatal UBSan, checking real transferred read endpoints, persistent state, endpoint permissions, stale/foreign/wrong-type rejection, independent duplicate lifetime and quota release. Fixture SVC numbers/results are artificial, not Horizon bindings. Existing event primitive/reference-SVC/zero-poll tests and runtime unit tests also pass after the shared allocator refactor. The old event unit-test source remains unchanged and its MIT adaptation hash is updated.

No production service binding, complete wait-any operation across independent event authorities, blocking/cancellation/clock model, real thread/process object or original game execution is provided. The CPU ABI and compiler acceptance rules remain unchanged. Required release targets include both new integration suites and the runtime unit tests. All prior tests/headers, identity/privacy checks and the complete supplied-binary/native/QEMU validation gate remain required.

## Explicit reference event handlers

[TABLE_EVENT_SERVICES.md](TABLE_EVENT_SERVICES.md) adds an opt-in event registry over these owned table endpoints, including zero-timeout polls within one shared event backend. It supplies no CreateEvent or IPC response. Real producers and final process permission filtering remain explicit; actual target/IPC/lifecycle validation remains open. [PROCESS_ENTROPY.md](PROCESS_ENTROPY.md) is a separate immutable process-state profile. Registries can combine only without conflicts and within the existing handler quota.
