# Explicit current-process memory queries

`ProcessMemory::new(Abi::Nx64IsolatedPrivatePages, budget)` supplies a narrow GetInfo profile over `OwnedMemoryBudget`. It assumes one isolated process whose accounted pages are private and non-system, with no external resource consumers or secure-memory charge. The caller explicitly configures its allowance as the process limit. This is not discovered RAM or verified Switch 2 resource policy.

The registry handles information types 21 (total non-system memory) and 22 (used non-system memory). Total returns the configured allowance; used snapshots live visible page usage, including fixed mappings and the visible heap, under the coherent memory lock. Code and stack mappings count once; hidden heap capacity is not current usage. Each query is individually linearizable. Two separate queries do not form an atomic pair.

Only W2 current-process pseudo handle `0xffff8001` is supported. All live bridge owners of the bound memory generation may query it. Foreign containers, replaced generations and invalid owners refuse. Other real/debug/current-thread handles remain unsupported; the profile does not invent a process handle table. W1 information type and W2 handle use their low 32 bits; X3 subtype uses all 64 bits. A nonzero subtype returns InvalidCombination before handle classification. Successful responses write W0 zero and the full X1 value. Errors preserve unspecified X1 without claiming retail failure-output bits.

`registry_with_entropy(&entropy)` explicitly dispatches types 11/21/22 through one GetInfo entry. Its entire registry is bound to the memory generation. Entropy retains its existing handle-before-subindex checks. `ProcessEntropy::registry()` remains unchanged and separately configurable. `Services::combined` still rejects duplicate service numbers; no generic fallback-after-error dispatch is introduced. Apply the final service allowlist after composition. Unknown information types remain unsupported.

Normal service completion clears the caller's exclusive monitor. Unsupported/foreign/denied calls preserve registers and reservations. A wrapper's later output store can fault after a completed query. No SDK initialization, process launch, target authorization or automatic registration occurs.

## Evidence and validation

Four additive debug/release tests exercise 80 native request/budget traces, 32 output-wrapper/budget/fault traces and 1,024 concurrent native queries while another owner resizes the heap. O0/O2 builds use fatal UBSan. Scope, generation, missing-entropy and allowlist refusals, full-width values, subtype precedence, monitor effects, duplicate registry rejection and failed resizes are covered. Prior tests/native headers remain unchanged and the release gate includes this suite. Existing QEMU transport checks remain required; QEMU Linux is not a Horizon GetInfo oracle.

Fresh identity-checked private inspection confirms the supplied startup memory query uses types 22/21 with the current-process handle and subtype zero. The existing page-layout probe preserves payloads, verifies BSS/padding and applies checked relocations without executing original functions. This service closes a bounded query dependency, not a complete startup closure. Actual limits/configuration, boot arguments, TLS/PAC and broader runtime services remain unverified.
